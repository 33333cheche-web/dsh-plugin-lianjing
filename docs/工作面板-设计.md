# 莲鲸 · 功课面板 设计

> 让桌宠顺手当 DSH 的状态指示灯：谁在跑、跑到哪、烧了多少。

## 0. 一句话

**不新建一个面板，而是给已有卡片加一页「功课」**；桌宠本体加一层「佛光」表示在跑，点开看会话，再点一行看子任务和数字。

---

## 1. 数据从哪来（已核实）

DSH 的会话数据是以 **projection（投影）** 的形式存在的，宿主算好、客户端直接订阅，天然推送、无需轮询。

`SessionProjectionMap` 里与本次相关的键（摘自 `@deepseek-ai/dsh-api-session-controller`）：

| 键 | 内容 | 用在 |
|---|---|---|
| `todos` | `[{content, status: 'completed' \| 'pending' \| 'in_progress'}]`，整表替换 | **任务 + 子任务** |
| `title` | 会话标题（最新 `session/title`） | 项目名 |
| `tokenUsage` | `uncachedInputTokens` / `outputTokens` / `cacheReadTokens` / `cacheWriteTokens` | **消耗的 token** |
| `contextPressure` | `pressureTokens` / `projectedTokens` / `contextWindow` | 上下文占用 |
| `contextBreakdown` | `systemTokens` / `toolsTokens` / `messageTokens` | 上下文构成 |
| `goal` | 持久目标 | 长期任务 |
| `plan` | 计划模式 | 可选 |
| `agentTeam` | Agent Teams | 可选 |
| `sessionStats` | 轮次、步骤、LLM / 工具 / 首 token / 解码 **墙钟时间** | **持续多久** |

另有两个非投影源：

- **`ctx.jobs`**：后台任务名册，流式推送。每行有生命周期、时长、实时 progress、终态 detail（`dsh-client-ui-jobs` 就是拿它渲染的）。
- **会话列表**：每行带 `sessionId` / `title` / `running` / `updatedAt` / `createdAt` / `agentAvailable`，冷会话还能带一份缓存投影提示。

**关键结论**：web 端插件能拿到上面这些。

- 客户端服务名是 **`ctx.sessions`**（`dsh-api-session-controller` 的 client 半场 `rootCtx.reflect.provide("sessions", …)`）。
- `ctx.sessions.getListSnapshot()` 直接给 `{ items, phase, projectionsBySession }`：`items` 是会话摘要（id / 标题 / running / updatedAt），`projectionsBySession[id].values` 就是上面那张投影表。
- 投影存储 `ProjectionValueStore` 提供 `get(key)` / `values()` / `subscribeAny()` / `faceOf(key)`，**是推送不是轮询**。
- `dsh-client-ui-conversation` 里的 `TodoPanel` 就是 `useProjection('todos')` 直接渲染的，说明这条路在浏览器里是通的。

> 落地时要在 `package.json` 的 `dsh.client.inject` 里声明依赖的包 id（参考 `dsh-client-ui-jobs`：它 inject 了 `dsh-api-job-controller` 等），保证加载顺序。

### 口径必须写清楚

- **「持续了多久」有两个含义**，不要混：会话从创建到现在的**墙钟时长**（`createdAt → now`），和 sessionStats 里**真正在 LLM / 工具上花的时间**。两个都给，标签写明白。
- **token 用投影里的数**，那是按会话日志回放算出来的，不是拍脑袋估的。界面上标明「本轮 / 全会话」。

## 2. 三层信息架构

### 第一层：不看也知道（立绘）

新增一层「**佛光**」：立绘后面一圈缓慢旋转的柔光。一开始是纯 CSS（`conic-gradient` + `mask`）画的细环，后来发现太硬、和桌面壳不是一个东西，改成两端共用同一张 `assets/halo.png`，网页端再 `blur(7px)` 糊开。

| 会话状态 | 立绘 | 佛光 | 角标 |
|---|---|---|---|
| 有空闲、无事 | 闭眼入定 | 无 | 未读经文数 |
| 有人在跑 | 闭眼入定（呼吸） | 金色缓慢旋转 | 在跑数 |
| 等工具/等审批 | 同上 | 金色 + 一圈小点流转 | 在跑数 |
| 全部收工 | 睁眼 1.5 秒 → 回定 | 收起 | — |
| 有失败 | 闭眼 | 暗红微闪 | ⚠ |

这层是**唯一的常驻提示**：不点她也能一眼看出"有没有在干活"。

## 3. 状态 → 眼神

沿用已实现的三眼神规则，只加两条**一次性**的：

| 时刻 | 动作 |
|---|---|
| 会话开始跑 | 抬眼 0.6s（「开工了」） |
| 全部完成 | 抬眼 1.5s（合十） |
| 跑失败 | **不新增表情**，只让佛光变暗红（新图成本高，先不做） |

「翻到下一句不睁眼」同理：**任务在跑时她不该一直睁眼**，否则又是干瞪眼。

---

## 4. 技术要点

1. **推送优先，不轮询**。投影是 push 的，jobs 是流。只有佛光那层用 CSS 动画，零开销。
2. **只在需要时订阅**。卡片收起时退订 jobs 流；佛光只订阅 `running` 这一个布尔。
3. **数据源分层降级**：
   - 有 `todos` → 显示子任务；
   - 没写过 todo（很常见）→ 显示后台 jobs + 最后活动时间；
   - 都没有 → 显示「今日无功课」，不编数据。
4. **不要把 agent 的解释当事实**：面板只显示结构化的投影字段，不做任何 AI 摘要。
5. **多会话 vs 当前会话**：见下面待定项。

## 6. 已知风险

| 风险 | 说明 | 对策 |
|---|---|---|
| 大多数会话没有 todo | `todo_write` 只有 agent 主动用才有 | 降级到 jobs + 时长，不显示空壳 |
| 投影键可能缺席 | 能力未组合时键不存在（`undefined`），不是空数组 | 每个字段都要有缺席分支 |
| 冷会话的投影是 `cached` | 可能是过期提示，不是权威值 | 列表上不拿它算精确统计 |
| 加了 client 依赖 | `dsh.client.inject` 里写错的包 id 会让插件加载失败 | 先只依赖最稳的两个包，跑通再加 |
| 卡片的宽度要变 | 功课页 480 vs 读经页 392 | 复用已有的 `measureCard`，把宽度也纳入测量 |

## 7. 拍板结果（已定）

1. **列表范围**：直接做**多会话列表**——一个会话 = 一个项目，不再只显示当前会话。
2. **桌面壳**：壳上**也要能点开面板**，所以数据不能只在浏览器里算，宿主必须出一条路由给两边共用。
3. **token 口径**：**只显示全会话累计**（这个项目一共烧了多少），不按轮次拆。

由此确定的架构：**宿主折叠、单一路由、两端只负责画**。

## 8. 接口契约（已实现并跑通）

`GET /dsh-lianjing/work.json`（免鉴权，给桌面壳）与 `GET /api/dsh-lianjing.work`（鉴权，给网页）返回同一份：

```json
{
  "ok": true,
  "now": 1793693619301,
  "totalSessions": 92,
  "runningCount": 0,
  "doneCount": 0,
  "sessions": [{
    "id": "session-1b8f…", "short": "1b8f1dfd",
    "title": "佛经学习插件开发计划", "project": "个人学习",
    "cwd": "D:\\cheche\\个人学习",
    "origin": "root", "parentId": "", "preset": "standard",
    "running": false, "live": false,
    "createdAt": 1793606905721, "lastPromptAt": 1793692056295,
    "durationMs": 86713580, "idleMs": 1563006,
    "todos": { "total": 5, "done": 0, "active": 1,
               "items": [{ "content": "…", "status": "in_progress" }] },
    "tokens": { "input": 12734853, "output": 579182,
                "cacheRead": 133818496, "cacheWrite": 0, "total": 147132531 },
    "stats": { "turns": 22, "steps": 1074, "llmMs": 16659823, "toolMs": 6300552 },
    "childCount": 1,
    "children": [{ "id": "…", "short": "ad46186b", "title": "…",
                   "running": false, "tokens": {}, "stats": {}, "todos": {} }]

```

实测：92 个会话里取 6 个根会话 + 各自最多 3 个子 agent；冷启动约 **1.2 秒**，命中缓存 **31 毫秒**。缓存策略：整份快照 2.5 秒、在跑会话的投影 3 秒、空闲会话的投影 20 秒。

### 8.1 「点一行跳回对话」的接力（v1.6.0）

网页端自己就能跳：客户端拿 `ctx.get('uiWorkspace')`（Cordis 服务名，DSH 侧边栏也是这么取的），调 `openSession(sessionId)`。

桌面壳是独立进程，够不到那个服务，所以走宿主接力：

```
壳  --POST /dsh-lianjing/open {"id":"session-…"}-->  宿主
                                                        └─ state.pendingOpen = { id, at }
网页 --每拍拉 /api/dsh-lianjing.state-->  看到 pendingOpen.at 变了
     └─ uiWorkspace.openSession(id)   （at 当去重键，处理过就不再理）
```

- 壳开着的时候，网页端轮询从 20 秒提到 **2.5 秒**（`shellUp ? 2500`），所以点完两三秒就跳过去。
- 宿主只收 `session-` 开头、长度受限的 id，别的一律 400；壳里失败会回一句「DSH 那边没接上」，不静默。
- 快照里 `pendingOpen` 只在内存里，不落盘——跳一次就过去了，重启没有残留。
